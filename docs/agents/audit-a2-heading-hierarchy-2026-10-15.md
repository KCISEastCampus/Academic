## 主要结论

用户观察到的层级弱化成立。原因涉及三个独立环节：

1. **正文的概念关系未完整编码。**制作时大量使用 H2 主题／学习阶段、H3 概念／推导／例题／题目的统一模板。对于较小主题，这种两层正文结构合理；对于内部已有多个模型或方法的长主题，把它们的专属示范继续平铺为 H3，就丢失了从属关系。还有一些新方法只在例题中出现，以及速查例题被放在不匹配的概念之后。
2. **共享样式压低了等级差异。**H2 为 1.35rem，H3 为 1.2rem，常见 16px 根字号下仅差 2.4px；颜色相同。移动规则又把 H1–H4 的间距统一为 `0.8rem 0 0.5rem`。手机实测 H2/H3 上边距均 12.8px，字重分别 700/600，标题与正文之间缺少足够清楚的视觉节奏。
3. **目录只展示 H2。**全部 90 页显式配置 `toc_headings: h2`，现有 H3/H4 不进入目录树及目录搜索。脚本能生成多级目录，但页面配置主动隐藏了这些级别。学习页中再把大批概念归入泛称的“例题”，目录更难支持按知识点回找。

此前审查主要验证标题是否被正确解析、是否跳级、双语 ID 是否一致，并把“没有技术结构异常”写得过于接近“层级清楚”。这些是必要技术检查，不能证明教学结构合理。本次将这一遗漏明确列为审查方法的问题。

## 合理结构与修复原则

目标是从标题树恢复“正在学什么、它包含哪些模型／方法、当前任务应用什么”。H1 课程页 → H2 独立主题 → H3 子概念／模型 → H4 必要的从属示范是一种适用的树；短主题直接采用 H2 → H3 示例也完全合理。综合练习可以独立 H2 → H3 题目，提示与解答保留可展开结构。无需每页都有四级，更不应为制造层级添加空的包装标题。

实施先调整真实父子关系和内容顺序，再处理 H2/H3/H4 的字号、字重和前后间距，最后根据实际查找任务决定目录纳入哪些子级。保留双语任务身份、必要公式和已有锚点；不能把全部题目盲目降为 H4，否则会错误归到最后出现的概念下。
